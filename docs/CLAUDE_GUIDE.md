# Руководство для Клауда: как работать с «Байт-прыгуном»

Прочитай это первым, потом `docs/ARCHITECTURE.md` (слои и правила, обязательно), потом `docs/MAP.md` (карта кода), потом нужные файлы. Владелец пишет с телефона и по-русски: отвечай по-русски, коротко, без воды.

## 1. Как зайти в репозиторий
Репозиторий публичный: `https://github.com/2gg4gg2-ship-it/byte-jumper`, ветка `main`. Ссылка сама доступа не даёт.
1. Есть bash: `git clone --depth 1 https://github.com/2gg4gg2-ship-it/byte-jumper`.
2. Нет bash, есть веб-чтение: `https://raw.githubusercontent.com/2gg4gg2-ship-it/byte-jumper/main/<путь>`; список файлов `https://api.github.com/repos/2gg4gg2-ship-it/byte-jumper/git/trees/main?recursive=1`.
3. Не получилось: не выдумывай содержимое, скажи что пробовал и попроси `byte-jumper.zip`.
Права на запись обычно нет (только чтение). Не коммить и не пушь, результат отдаёшь zip-файлом.

## 2. Перед каждой работой
- Заново прочитай `main` и версию (`app/build.gradle.kts`). Над проектом могут работать другие Клауды: не затирай чужие правки, сначала разберись, что изменилось, потом переноси свои.
- Открой `docs/MAP.md`: таблица «хочу изменить X → файл» и индекс функций с номерами строк избавляют от чтения всего кода.

## 3. Правила кода
- Логика без DOM и рисование без логики (границы в `docs/MAP.md`). Игра офлайн: никакой сети, библиотек, внешних картинок (кроме атласа героя `spark/spark.png`).
- Текст в DOM только через `textContent`. Эмодзи не использовать.
- Перед каждой атакой босса предупреждение 0,5–1,2 с, не больше 20 снарядов на экране, всегда есть безопасное окно.
- Тексты сюжета не переписывай: источник `docs/STORY_BIBLE.md`, `story.js` из него сгенерирован.
- Пути файлов игры не менять (возврат в Kairema, `docs/RETURN_TO_KAIREMA.md`).
- Файл больше ~450 строк режь на части.

## 4. Проверки (запускай перед отдачей, длинные с выводом в файл)
- `node docs/tests/engine.test.js` (логика: прыжки, боссы, уровни)
- `node docs/tests/levels.test.js` (долго, ~1 мин: бот проходит уровни 1–29)
- `python3 -I docs/tests/standalone.test.py` (Playwright, Chromium 360x780: меню, бой, нет ошибок страницы)
- `python3 -I docs/tools/check_arch.py` (архитектура: слои, зависимости, размер файлов)
- `python3 -I docs/tools/make_map.py --check` (карта актуальна)
- Для вида: скриншоты Playwright (`deviceScaleFactor` 2), посмотри их сам.

## 5. Как отдавать работу
CI (`.github/workflows/build.yml`) берёт любой `./*.zip` из корня репозитория, делает `rm -rf app settings.gradle.kts`, распаковывает и собирает APK (релиз `latest`, файл `ByteJumper.apk`). Поэтому:
- Архив **всегда полный**: `app/ docs/ README.md settings.gradle.kts .gitignore`. Частичный архив сотрёт приложение. Не клади `.github/`, ключи, пароли, видео.
- Сборка из корня проекта: `zip -qr ../byte-jumper.zip app docs README.md settings.gradle.kts .gitignore`.
- Версия при каждой отдаче (в трёх местах): `app/build.gradle.kts` (строки со знаком `=`: `versionCode = N`, `versionName = "X.Y.Z"`; после правки проверь `grep`), `README.md`, строка сверху в `docs/CHANGELOG.md`. Потом `python3 docs/tools/make_map.py`.
- Отправь zip вложением (не простынёй кода). Скажи владельцу залить его в **корень** репозитория: `https://github.com/2gg4gg2-ship-it/byte-jumper/upload/main` (не в папку `.github/workflows`). После сборки версия в приложении должна совпасть.

## 5а. Вставка в Kairema
`python3 docs/tools/sync_to_kairema.py <путь_к_kairema> [--apply]`, подробности в `docs/RETURN_TO_KAIREMA.md`. Источник правды об игре этот репозиторий; в Kairema игру руками не правят.

## 6. Честность
В конце два списка: **Проверено** (что реально запускал и видел) и **Не проверено** (сборка APK, игра на телефоне, ощущение управления, баланс). Не пиши «готово» про то, что не запускал.

## 7. Если не уверен
Лучше короткий вопрос владельцу, чем большая работа в неверную сторону. Но если задача ясна, начинай сразу и сообщай только о важном.
