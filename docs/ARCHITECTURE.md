# Архитектура «Байт-прыгуна»

Обязательно для всех Клаудов. Проверяется скриптом: `python3 docs/tools/check_arch.py` (нарушения = код возврата 1). Карта файлов и функций: `docs/MAP.md`.

## 1. Общая схема

```
Android (Kotlin, MainActivity.kt)  →  WebView  →  assets/index.html
     мост один: Android.exit()           shim/shim.js (заглушка ядра Kairema)
                                              ↓
                          features/game/*  (вся игра, чистый JS + canvas, офлайн)
```

Игра написана для Kairema и живёт в `features/game`. `shim/` существует только для отдельного приложения; в Kairema его заменяет ядро Kairema. Поэтому **пути `features/game/*` менять нельзя** (`docs/RETURN_TO_KAIREMA.md`).

## 2. Четыре слоя внутри `features/game`

| Слой | Файлы | Что делает | Что ему можно / нельзя |
|---|---|---|---|
| 0. Ядро | `core.js` | шаг 1/60 с, авто-качество | не знает никого |
| 1. Логика | `engine.js`, `levels.js`, `story.js`, `arena.js` | правила, физика, уровни, босс-ИИ, данные сюжета | знает слой 0 и друг друга; **не трогает DOM, `window`, `localStorage`, canvas**, не знает про рисование и экраны. Проверяется в node |
| 2. Рисование | `art.js`, `bossart.js`, `levelview.js`, `spark.js`, `fx.js` | всё, что видно на canvas | читает состояние `S` и константы логики; **не решает правил**, не меняет `S` (кроме своего локального состояния анимации), не знает про экраны (`Game`, `GameStoryUI`) |
| 3. Экраны и склейка | `game.js`, `storyui.js` | меню, ввод пальцами, цикл, пауза, звук, сохранение, оверлеи | знает всё; единственное место, где есть `localStorage`, `Audio`, pointer-события, `requestAnimationFrame` |

Поток данных: ввод (game.js) → `GameEngine.step` / `GameArena.step` (логика меняет `S`) → рисование читает `S` (art/bossart/levelview/spark/fx) → экран. Состояние забега `S` живёт только в `game.js` (`start`), логика получает его параметром.

## 3. Правила

1. Новая логика (атака босса, правило уровня) только в слое 1, новое рисование только в слое 2, ввод и сохранение только в слое 3.
2. Босс N = три вещи: набор атак `kitN` в `arena.js`, рисунок в ветке `id===N` в `bossart.js`, тексты в `story.js` (из `docs/STORY_BIBLE.md`). Новый босс не требует правок других файлов, кроме записи в таблицу `KITS`.
3. Уровень N = строка сценария в `levels.js` (слой 1) и, если нужны новые препятствия, их рисование в `levelview.js` (слой 2).
4. Сохранение: один ключ `kairema.game.v1`, поля читаются и пишутся только в `game.js` (`load`/`save`). Новое поле: добавь значение по умолчанию в `load`, чтобы старые сохранения не ломались.
5. Тексты для игрока: сюжет только из `STORY_BIBLE.md` → `story.js`; в DOM только `textContent`.
6. Без сети, без библиотек, без эмодзи. Один файл ≤ 450 строк, иначе режь на части (это предупреждение скрипта).
7. Новый файл игры: добавь `<script>` в `index.html` до `game.js`, строку в таблицу `MOD` в `docs/tools/check_arch.py` и в таблицу слоёв выше, затем `python3 docs/tools/make_map.py`.
8. Каждое изменение: тесты (список в `docs/CLAUDE_GUIDE.md`), версия в трёх местах, `make_map.py`, `check_arch.py`, полный zip.

## 4. Тесты по слоям

- Слой 1 (логика): `node docs/tests/engine.test.js`, `node docs/tests/levels.test.js` (долго).
- Слои 2–3 (вид и экраны): `python3 -I docs/tests/standalone.test.py` + скриншоты Playwright.
- Архитектура и карта: `python3 -I docs/tools/check_arch.py`, `python3 -I docs/tools/make_map.py --check`.

## 5. Что сознательно не сделано (честно)

- `game.js` (~335 строк) содержит и экраны, и цикл, и звук. Пока ему не тесно; если вырастет за 450, выноси звук в `sound.js` и сохранение в `save.js` (слой 3).
- Есть известное отклонение: `engine.js` вызывает `GameLevels` (подключён позже в `index.html`), но только внутри функции с проверкой `typeof`; скрипт выводит это как предупреждение.
- Автоматических тестов самого Kotlin нет: его компилирует только CI.
